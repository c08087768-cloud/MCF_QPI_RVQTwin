# 故障排查

## 1. CUDA 不可用

```bash
python -c "import torch; print(torch.__version__, torch.version.cuda, torch.cuda.is_available())"
```

常见原因：安装了 CPU wheel、驱动过旧、容器没有挂载 GPU。

## 2. 下载中断

重新执行相同命令。`.part` 临时文件会用于续传；服务器不支持 Range 时会安全地从头覆盖，而不是错误追加。

## 3. 解压后配对为 0

先看：

```text
outputs/data_inspection/raw_structure.json
```

根据真实目录名称，修改：

```text
src/mcfqpi/data/pairing.py
SPECKLE_WORDS
PHASE_WORDS
```

不要直接启用顺序配对后跳过人工检查。

## 4. HDF5 worker 报错

HDF5 文件句柄不能在多进程间直接共享。`MCFH5Dataset` 已按 worker 延迟打开。仍有问题时先设置：

```yaml
num_workers: 0
persistent_workers: false
```

## 5. VQ 码本塌缩

表现：perplexity 接近 1，大部分 token 相同。处理：

- codebook 256 → 128；
- VQ loss 权重降低；
- 先提高自编码器重构质量；
- warm-up 后再加 token 对齐；
- 检查标签是否被错误二值化。

## 6. forward twin 很差

这是可能的，因为 phase→单幅 speckle 映射对网络容量和系统稳定性要求高。直接关闭 cycle loss，并把它作为负结果/消融，而不是强行增大权重。

## 7. 训练很好但跨域很差

这是数据分布问题，不一定是代码错误。检查：

- digits/fashion 是否分别报告；
- 是否做了几何增强造成虚假映射；
- 模型是否只记住标签形状先验；
- RVQ 码本是否缺少 Fashion 高频结构；
- 加入 strict split 和低数据实验。

## 8. 扩散评估太慢

先用 25 个 DDIM steps，batch 1–8；确认流程后再跑 50/100 步。所有结果注明采样步数。

## 9. ONNX 导出失败

双域模型包含 `torch.fft` 和量化操作，部分 ONNX 版本不支持。工程的 ONNX 脚本主要用于 ResUNet 基线。主模型部署优先使用 PyTorch、`torch.compile` 或后续针对目标平台重写 Fourier 分支。
