# MCF-QPI 主网络（阶段五 §2.7）参数配置说明

> 本文件记录主网络 `DualDomainRVQTwin`（配置 `configs/research/proposed_rvqtwin.yaml`）在
> 2026-08 当前状态下所有参数、它们的来源，以及方案 B（调参反超）的调整建议。
> 方案文档 `MCF-QPI_方案.md` 对应章节：§2.3（相位先验）、§2.7（主网络）、§2.7.5（总损失）。

---

## 0. 一句话结论

**当前所有参数 = 方案文档约定的默认值 + 工程脚手架经验惯例值，没有任何一项是在 MCF-QPI 数据上系统搜索出来的。** 参数来源分两类：

- **方案定死**：结构开关、残差缩放 α、码本冻结策略 —— 在 `MCF-QPI_方案.md` 里写明了值。
- **经验默认**：损失权重、训练超参、base_channels —— 靠"主监督项占主导、辅助项偏小"的直觉设的，未经数据验证。

方案 B 的目标，就是把这些"经验默认"通过 val 集系统调参变成有依据的值。

## 1. 相位先验参数（`model.phase_prior_model.*`）

继承**阶段一 Phase-RVQ-VAE**（`configs/research/phase_rvqvae.yaml`）的默认配置，来源见方案 §2.3「默认配置」表。

| 参数 | yaml 字段 | 当前值 | 来源 | 方案 B 建议 |
|------|----------|--------|------|------------|
| 潜变量通道数 | `latent_channels` | 64 | 方案 §2.3 默认表 | 不动（先验已训好，改动需重训先验） |
| 下采样次数 | `downsample_stages` | 3（潜空间 16×16） | 方案 §2.3 默认表 | 不动 |
| 码本级数 K | `num_quantizers` | 2 | 方案 §2.3 默认表 | 不动 |
| 每级码本大小 | `codebook_size` | 256 | 方案 §2.3 默认表 | 不动 |
| commitment β | `commitment_beta` | 0.25 | 方案 §2.3 默认表 | 不动 |
| 先验内部基础通道 | `base_channels` | 32 | 脚手架默认 | 不动 |

> 这组参数与冻结的 `phase_rvqvae_seed*/best.pt` 绑定，主网络加载先验时**必须与训练先验时一致**，否则权重对不上。所以方案 B 一律不动这组。

### 1.1 上游根因：阶段一码本健康度差（perplexity 低）

主网络挂载的先验码本来自阶段一，但**阶段一训出来的码本本身不健康**——这是主模型负结果的上游根因，先于任何主网络调参。实测（`outputs/research/phase_prior_eval_seed42/codebook_statistics.csv`，seed42）：

| 码本级   | 码本大小 | 用到码字 | 死码  | 死码比例      | 经验 perplexity | 归一化 perplexity |
| ----- | ---- | ---- | --- | --------- | ------------- | -------------- |
| 第 1 级 | 256  | 104  | 152 | **59.4%** | 43.9          | **0.171**      |
| 第 2 级 | 256  | 256  | 0   | 0%        | 106.5         | 0.416          |

**判读**：
- **归一化 perplexity** = `经验 perplexity / codebook_size`，范围 [0,1]；接近 1 表示码字被均匀使用（健康），接近 0 表示只用了极少数码字（collapse）。
- 第 1 级归一化 perplexity **0.171**，且死码比例 **59.4%**（256 个码字里 152 个完全没被用到）——**第一级码本严重 collapse**，实际只靠 ~44 个码字在表征相位主体结构，覆盖严重不足。
- 第 2 级健康（0 死码、perplexity 0.42），说明细节残差层面够用。

**含义**：主网络挂载了一个"主体结构塌缩"的先验码本，离散约束不可靠——这直接呼应消融 `dual_continuous`（关掉量化指标不变）：**因为码本本身就不健康，挂载它当然没有正增益**。这不是主网络调参能救的，得修先验。

**修复方向**（方案 §2.3 检查项原文："若 perplexity 很低，先降低码本规模或 VQ 权重，而不是继续增大网络"）：

| 方向 | 做法 | 预期 |
|------|------|------|
| 降码本规模 | 第一级 `codebook_size` 256→128 或 64 | 减少死码，perplexity 回升 |
| 降 VQ 权重 | 阶段一训练时调低 commitment 损失 | 放松码本对齐压力 |
| 用 EMA 更新码本 | 若当前是 SGD 更新，改 EMA | 码字利用率更高 |

> 改先验需**重训阶段一**（`train_phase_rvqvae.py`），再重训主网络，成本高于纯调主网络，但这是治本。

## 2. 主网络结构参数（`model.*`）

| 参数 | yaml 字段 | 当前值 | 来源 | 方案 B 建议 |
|------|----------|--------|------|------------|
| 编码器基础通道 | `base_channels` | 32 | 脚手架默认（与 ResUNet 基线 32 保持可比） | **32→48**，提高双域编码器表达力 |
| dropout | `dropout` | 0.10 | 脚手架默认（比先验 0.05 大，防过拟合） | 可试 0.05~0.15 |
| 连续残差缩放 α | `residual_scale` | **0.15** | 方案 §2.7.2 明写 "α=0.15" | **0.15→0.3~0.5**，放宽连续支路表达 |
| 空间分支开关 | `use_spatial` | true | 方案 §2.7.1 双域设计 | 保持 true |
| 频域分支开关 | `use_frequency` | true | 方案 §2.7.1 双域设计 | 保持 true（消融证明它约有 4% 边际增益） |
| 量化开关 | `use_quantization` | true | 方案 §2.7.2 默认 | 保持 true（关掉也不变好，见消融） |
| 冻结先验编码器 | `freeze_prior_encoder` | true | 方案 §2.3 "编码器 E 不再需要" | 保持 true |
| 冻结码本 | `freeze_codebook` | true | 方案 §2.3 "码本 C 冻结" | 保持 true |
| 冻结先验解码器 | `freeze_decoder` | **false** | 与方案 §2.3 "解码器 D 不再需要" **不一致** | 可试 **true**，看彻底锁死先验是否减干扰 |

> **注意 `freeze_decoder: false` 与方案文档不一致**：方案 §2.3 说解码器训完先验后"不再需要"，但当前 yaml 让先验解码器在主网络里继续参与梯度更新。这是方案定死值与实际配置的已知偏差，方案 B 时可一并核对。

## 3. 损失权重（`loss.*`，对应方案 §2.7.5 的 λ）

方案 §2.7.5 只给符号和公式，**未给数值**；以下数值是脚手架作者按"主监督 1.0 + 辅助项偏小"的直觉设的。

| 方案符号 | 含义                | yaml 字段          | 当前值      | 性质     | 方案 B 建议               |
| ---- | ----------------- | ---------------- | -------- | ------ | --------------------- |
| λ1   | 相位 MAE            | `phase_l1`       | 1.0      | 主监督，锚点 | 不动                    |
| λn   | Laplace NLL（不确定度） | `phase_nll`      | 0.05     | 不确定度   | 不动                    |
| λg   | 梯度误差              | `gradient`       | 0.15     | 结构监督   | 不动                    |
| λs   | SSIM              | `ssim`           | 0.20     | 结构监督   | 不动                    |
| λρ   | 相关系数              | `pearson`        | 0.05     | 结构监督   | 不动                    |
| λt   | token 交叉熵         | `token`          | **0.15** | 先验正则   | **0.15→0.05**         |
| λz   | 潜变量对齐             | `latent`         | **0.10** | 先验正则   | **0.10→0.03**         |
| λv   | VQ commitment     | `vq`             | **0.05** | 先验正则   | **0.05→0.02**         |
| λc   | cycle L1          | `cycle_l1`       | 0.05     | 闭环正则   | 见下方说明                 |
| —    | cycle 频谱          | `cycle_spectral` | 0.02     | 闭环正则   | 见下方说明                 |
| λr   | 连续残差 L1           | `residual`       | 0.01     | 残差正则   | 可升到 0.02~0.03 配合 α 放宽 |

### 为什么砍 token / latent / vq

实测证据（见 `docs/14_实验结果分析报告.md` §4）：

- `token` 项全程维持在 **4.5 量级**，而 `phase_l1` 收敛到 **0.018** —— 先验正则项的绝对值是主监督项的 250 倍，把优化方向从"相位准"拉向"码本对齐"。
- 消融 `dual_continuous`（关掉 VQ/token）指标不变，证明这些先验项**没有正贡献**，只是稀释优化。

因此方案 B 第一刀砍这三个权重，让主监督项重新主导梯度。

### cycle 权重怎么办

消融 `no_forward_twin`（cycle 全 0）指标与完整模型几乎相同（MAE 0.0493 vs 0.0497），说明 cycle **既没帮助也没明显拖累**。两个选择：

- **保守**：先保持 0.05/0.02 不动，等 token/latent/vq 调完看效果；
- **激进**：直接归 0，等效于 no_forward_twin 消融，简化优化。

## 4. 训练超参（`training.*`）

| 参数      | yaml 字段                   | 当前值    | 来源                     |
| ------- | ------------------------- | ------ | ---------------------- |
| 总 epoch | `epochs`                  | 80     | 脚手架默认，配早停              |
| 早停耐心    | `early_stopping_patience` | 15     | 脚手架默认                  |
| 优化器     | `optimizer.name`          | adamw  | 惯例                     |
| 学习率     | `optimizer.lr`            | 1.5e-4 | 惯例（128×128 + AMP 经验起点） |
| 权重衰减    | `optimizer.weight_decay`  | 1e-4   | 惯例                     |
| 调度器     | `scheduler.name`          | cosine | 惯例                     |
| 最小学习率   | `scheduler.min_lr`        | 1e-6   | 惯例                     |
| 混合精度    | `amp`                     | true   | 惯例                     |
| 梯度裁剪    | `gradient_clip`           | 1.0    | 惯例                     |

> 训练超参全是惯例值。若方案 B 砍先验权重后模型"欠拟合"（val 曲线不再下降），可考虑 `lr 1.5e-4→3e-4` 或 `epochs 80→120`，但先别动，等第一轮调参结果出来再判断。

## 5. 方案 B 调整速查表（一页汇总）

| 改动 | yaml 路径 | 当前值 | 目标值 | 优先级 |
|------|----------|--------|--------|--------|
| 砍 token 权重 | `loss.token` | 0.15 | 0.05 | ★★★ |
| 砍 latent 权重 | `loss.latent` | 0.10 | 0.03 | ★★★ |
| 砍 vq 权重 | `loss.vq` | 0.05 | 0.02 | ★★★ |
| 放宽残差缩放 | `model.residual_scale` | 0.15 | 0.30 | ★★ |
| 提升编码器容量 | `model.base_channels` | 32 | 48 | ★★ |
| 锁死先验解码器 | `model.freeze_decoder` | false | true（可选） | ★ |
| cycle 归零（可选） | `loss.cycle_l1` / `cycle_spectral` | 0.05/0.02 | 0/0 | ★ |

**调整纪律**：
1. 所有调参只在 **val 集**看效果，test 只跑最终一次（`START_HERE_中文.md §5`）。
2. 每次只改一组因素，做单因子消融，别一次全改。
3. 先跑 ★★★ 三项（砍先验权重），若 val 相位 L1 降到 ≤ baseline 的 0.014 附近，再逐项加 ★★。
