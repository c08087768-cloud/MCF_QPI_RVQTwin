# 近期实验与结果总结（2026-08 下旬）

> 本文是最近一轮"主模型（proposed RVQ-Twin）落后于基线"诊断与调参的**阶段性总结报告**。
> 它串起三份前置文档的结论，面向阅读而非过程记录：
> - `docs/14_实验结果分析报告.md` —— 原始三种子主表与负结果分析；
> - `docs/16_阶段一码本利用率改进实验.md` —— 先验码本侧的单变量实验；
> - `docs/17_主模型调参前本地审查.md` —— 步骤 1/2 的代码审查与统一验证口径。
>
> 所有数值均来自落盘的 `outputs/local_audit_20260829/*.json`，已核对一致。

---

## 0. 一句话结论

**经过系统排查，proposed 主模型落后于 baseline 的主要原因不是网络架构、不是相位先验、也不是 token 损失权重，而是"训练数据增强过强"**——它损害了 clean 验证精度。把 proposed 的增强强度对齐到 baseline 后，clean val MAE 下降 7.32%，且 digits / fashion 两个域同步改善，方向明确、幅度超过种子波动。

---

## 1. 起点：一个必须解释的负结果

原始三随机种子主表（`docs/14 §2`）显示主模型全面落后：

| 模型 | test MAE(rad) | 2D相关 |
|------|--------------|--------|
| paper_style_resunet | 0.0265 | 0.9970 |
| baseline_resunet | 0.0427 | 0.9919 |
| proposed_rvqtwin | 0.0497 | 0.9895 |

proposed 比 baseline 差约 14%，且无法靠消融翻盘。这引出了一个问题：**差距到底来自架构本身，还是来自训练条件的不对等？** 于是启动了这轮诊断。

---

## 2. 第一步：审查发现"三个模型根本不是单一变量对照"

不做训练，先核对代码与 `resolved_config.yaml`，结果发现三个模型的**训练条件差异远不止网络结构**（详见 `docs/17 §1`）：

| 项目    | paper_style | baseline              | proposed                            |
| ----- | ----------- | --------------------- | ----------------------------------- |
| 数据增强  | **关闭**      | 较弱                    | **最强**                              |
| 高斯噪声  | 无           | 0.01                  | 0.015                               |
| 模糊概率  | 无           | 0.10                  | 0.15                                |
| 增益/背景 | 无           | 0.10/0.02             | 0.15/0.03                           |
| 优化器   | Adam        | AdamW                 | AdamW                               |
| 学习率   | 1e-4        | 2e-4                  | 1.5e-4                              |
| 主监督损失 | 仅 L1        | L1+grad+ssim+corr+nll | 同左 + token/latent/VQ/residual/cycle |

**结论**：原差距混入了增强、损失、优化器、推理口径（MC 1 vs 8）等多重混杂，不能把差距全归于架构。这成为后续实验的出发点。

同时排除了两个"非主因"：
- **checkpoint 选择**（按总 val_loss 而非相位 MAE 选 best）：三种子下 best.pt 与相位 L1 最优轮的差距仅 0.06%–0.21%，量级太小。
- **冻结与梯度**：先验编码器/码本/forward twin 冻结正常，cycle 梯度通路未断。

---

## 3. 第二步：统一口径下复评（不改权重，只重评）

在 CPU FP32、MC=1、关闭增强、同一批 6000 个 clean val 样本下重评，结果排序**不变**（`docs/17 §5.3`）：

| 模型 | Val MAE(rad) | Val SSIM | digits MAE | fashion MAE |
|------|-------------|----------|-----------|-------------|
| paper_style ResUNet | 0.025707 | 0.981991 | 0.015796 | 0.037820 |
| baseline ResUNet | 0.042953 | 0.961763 | 0.027298 | 0.062086 |
| proposed RVQ-Twin | 0.049078 | 0.953013 | 0.031732 | 0.070279 |

**结论**：统一口径后 proposed 仍落后 baseline 14.26%，且 digits、fashion 两个域都更差——排除了"MC 采样口径不同"这个解释。问题真实存在，且**同时存在于两个域**，不是混合比例造成的假象。

---

## 4. 支线：先验码本实验（未通过，不替换）

在正式调主网络前，先验证了 `docs/14 §4.1` 提出的"先验码本第一级利用不足"是否为根因。单变量对照两个新先验（`docs/16`）：

| 先验 | Val MAE(rad) | Val SSIM | 第一级使用 | 判定 |
|------|-------------|----------|-----------|------|
| **original 256 / VQ 0.50** | **0.008381** | **0.998325** | 105/256 | ✅ 保留 |
| codebook128 / VQ 0.50 | 0.009138 | 0.998035 | 106/128 | ❌ 重建变差 |
| codebook256 / VQ 0.25 | 0.008828 | 0.998189 | 99/256 | ❌ 重建变差 |

**结论**：缩码本或降 VQ 权重**没有改善重建**，反而让重建 MAE 变差。原始先验的重建上限已经很高（MAE 0.0084），第一级"利用不足"不是主模型落后的根因。**不替换先验**，继续用原始 checkpoint。

---

## 5. 核心实验一：token 权重单变量（无改善，不采用）

按审查结论，最值得先验证的假设是 `loss.token` 权重（0.15→0.05），其余全部保持。结果（seed42，同口径 clean val）：

| 模型 | Val MAE(rad) | Val SSIM | digits MAE | fashion MAE |
|------|-------------|----------|-----------|-------------|
| 原 proposed（token=0.15） | 0.049078 | **0.953013** | **0.031732** | 0.070279 |
| token=0.05 | 0.048975 | 0.952745 | 0.031813 | 0.069950 |

**结论**：MAE 仅改善 0.21%（绝对下降 0.000104 rad），fashion 改善 0.47% 但 digits 反而恶化 0.25%，SSIM 下降。改善幅度**远小于三随机种子的标准差（约 0.000649 rad）**，不能判定为可靠改进。

**决定**：不替换主模型，不为 token=0.05 跑 test 或追加种子。token 项不是主因。

---

## 6. 核心实验二：增强强度对齐（明确改善，当前候选配置）

把目光转向审查中最突出的混杂因素——**数据增强**。proposed 的增强远强于 baseline。单变量实验：只把 proposed 的整组增强对齐到 baseline 水平，其余全部保持（含 `token=0.15`）。

| 模型 | Val MAE(rad) | Val SSIM | digits MAE | fashion MAE |
|------|-------------|----------|-----------|-------------|
| 原 proposed（强增强） | 0.049078 | 0.953013 | 0.031732 | 0.070279 |
| token=0.05（强增强） | 0.048975 | 0.952745 | 0.031813 | 0.069950 |
| **增强对齐 baseline** | **0.045484** | **0.959125** | **0.029745** | **0.064721** |

**相对原 proposed 的改善**：

| 指标 | 变化 |
|------|------|
| 总体 MAE | **↓ 7.32%** |
| digits MAE | ↓ 6.26% |
| fashion MAE | ↓ 7.91% |
| SSIM | ↑ 0.006112 |

**结论**：
1. 改善幅度是 token 实验（0.21%）的 **35 倍**，且**远超三随机种子波动**（0.000649 rad）。
2. **两个域、两项主指标（MAE↓、SSIM↑）方向完全一致**，不是单一域的偶然。
3. 服务器 GPU AMP 与本地 CPU FP32 结果一致，排除了推理硬件口径造成改善的可能。

**判定**：**较强的训练增强是原 proposed clean 精度损失的重要来源**，增强对齐 baseline 是当前有效候选配置。

**保留的谨慎**：本实验一次联动了 6 个增强项（噪声/模糊/增益/背景/饱和/坏点），只能归因到"增强方案整体"，不能认定某一个增强项是唯一根因。

## 8. 结论与下一步

### 8.1 已确认的结论

1. **架构不是主因**：统一口径后 proposed 仍落后，但差距被训练条件（尤其增强）大幅放大。
2. **先验不是主因**：原始先验重建上限已很高，缩码本/降 VQ 都变差，不替换。
3. **token 不是主因**：单变量降 token 无可靠改善。
4. **增强过强是重要主因**：对齐 baseline 后改善 7.32%，两域一致，超过种子波动。

### 8.2 下一步（按优先级）

1. **验证稳定性**：增强对齐当前只有 seed42。对候选配置补 **seed123 和 seed2026**，仍然只评估 clean val，三个种子都稳定改善后，再冻结配置、跑最终 test。
2. **可选：拆分增强项**：若需要定位到具体哪个增强项（噪声/模糊/增益…）最伤 clean 精度，可做单因子拆解，但**不能和稳定性验证混跑**。
3. **正式替换**：三种子确认后，把增强对齐配置定为新主模型，更新 `configs/research/proposed_rvqtwin.yaml` 的 augmentation 段，再跑 test。

### 8.3 纪律提醒（沿用至今）

- 所有选择只依据 **clean val**，**尚未查看 test**（test 只在最终冻结后跑一次）。
- 已有 test 结果（`docs/14`）在讨论中出现过，后续报告必须披露这一点，不能称其为"从未查看的测试集"。
- 每次只改一个变量；token 与增强是分开的两轮，未混跑。
