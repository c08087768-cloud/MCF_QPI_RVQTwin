# 阶段一码本利用率改进实验

## 1. 问题与基线

Phase-RVQ-VAE 使用两级 Residual VQ，每级码本大小为 256。三个随机种子的测试集码本统计如下。

| Seed | 第一级死码率 | 第一级归一化 perplexity | 第二级死码率 | 第二级归一化 perplexity |
|---:|---:|---:|---:|---:|
| 42 | 59.4% | 0.171 | 0% | 0.416 |
| 123 | 37.1% | 0.314 | 0% | 0.430 |
| 2026 | 56.6% | 0.192 | 0% | 0.420 |

结论：第一级码本在三个随机种子下均出现利用不足，但不应表述为“完全坍缩”。第二级码本利用健康。当前实现用普通反向传播更新 `nn.Embedding`，未使用 EMA 或死码重置。

## 2. 实验目标

判断第一级利用不足主要来自：

1. 码本规模 256 相对当前潜空间分布过大；
2. 阶段一总损失中 `loss.vq: 0.50` 约束过强。

本轮不修改 `src/mcfqpi/models/rvq.py`，也不引入 EMA，先做两个单变量对照。

## 3. 实验矩阵

| 实验 | 唯一变量 | 基线值 | 实验值 | 其余设置 |
|---|---|---:|---:|---|
| Baseline | 无 | codebook=256, VQ=0.50 | — | 原始结果 |
| A: codebook128 | `model.codebook_size` | 256 | 128 | 与 baseline 完全相同 |
| B: vq025 | `loss.vq` | 0.50 | 0.25 | 与 baseline 完全相同 |

注意：`commitment_beta: 0.25` 是量化器内部的 commitment 项系数；`loss.vq` 是 PhasePriorLoss 中整个 VQ 损失的外部权重。本轮只调后者。

## 4. 服务器执行

将本次新增的 `configs/`、`scripts/` 和 `docs/` 上传到服务器项目根目录，然后执行：

```bash
conda activate mcf-qpi
cd /home/user/MCF_QPI_RVQTwin
MCFQPI_DEVICE=cuda:1 SEED=42 \
  nohup bash scripts/run_phase_prior_codebook_experiments.sh \
  > codebook_experiments_seed42.log 2>&1 &
```

查看进度：

```bash
tail -f codebook_experiments_seed42.log
nvidia-smi
```

两组实验串行使用 1 号 GPU，不会占用 0 号 GPU。按既有阶段一耗时估计，两组合计约 3.5–4 小时。

## 5. 产物位置

```text
outputs/codebook_experiments/
├── codebook128_seed42/          # 训练权重与曲线
├── eval_codebook128_seed42/     # 重建指标与码本统计
├── vq025_seed42/                # 训练权重与曲线
└── eval_vq025_seed42/           # 重建指标与码本统计
```

重点文件：

- `eval_*/codebook_statistics.csv`：死码率、perplexity；
- `eval_*/summary.json`：重建 MAE、SSIM、PSNR；
- `<experiment>/history.json`：训练曲线；
- `<experiment>/best.pt`：若实验通过，供主网络重训使用。

## 6. 预先约定的判定标准

不只看 perplexity，必须同时看码本利用率和重建质量。

| 指标 | 基线 | 期望方向 | 初步通过条件 |
|---|---|---|---|
| 第一级死码率 | 37%–59% | 降低 | ≤25% |
| 第一级归一化 perplexity | 0.17–0.31 | 提高 | ≥0.35 |
| 第二级死码率 | 0% | 不恶化 | ≤5% |
| 相位先验重建 MAE/SSIM | 见基线 summary | 不恶化 | MAE 增幅≤2%，SSIM 降幅≤0.005 |

这些阈值是实验筛选标准，不是理论定律。若 A/B 均无法改善第一级利用率，才进入第二轮：评估 EMA 码本更新和死码重置，届时需修改 `rvq.py` 并补单元测试。
